# Figure it out

Use this skill for large migrations, multi-part changes, or work that needs an audit trail. Use a narrower workflow for focused bugs, features, or reviews.

1. Define done as a falsifiable predicate.
2. Quantify scope, effort, blockers, and the required rigor.
3. Decompose the work into independently verifiable units.
4. Build or identify the verification harness before changing the artifact.
5. Sequence the riskiest unknowns first.
6. Parallelize only across genuine seams, with isolated workspaces or outputs.
7. Treat each unit as an experiment: state the hypothesis, make the smallest change, verify it, and keep or discard it.
8. Record decisions, evidence, failed attempts, and unresolved questions.
9. Verify the whole result against the original predicate.

Return the playbook, rigor level, decision trail, verification evidence, and open risks.
